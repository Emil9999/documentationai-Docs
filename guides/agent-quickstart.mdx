Connect your AI coding agent (Cursor, Claude Code, Claude Desktop, Windsurf, VS Code Copilot, or custom LLM workflows) directly to Kini's live documentation and API reference.

Kini provides a dedicated [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) reader endpoint at `https://docs.getkini.com/_mcp`. Connecting your agent gives it real-time access to endpoint schemas, authentication rules, webhook payloads, and error codes while writing code.

---

## Step 1: Connect your Agent via MCP

Configure your coding agent or MCP client to connect to the Kini Docs MCP server.

<Tabs>
  <Tab title="Cursor" icon="sparkles">
    Add the Kini Docs MCP server to `.cursor/mcp.json` in your project root, or configure it globally in **Cursor Settings → Features → MCP**:

    ```json .cursor/mcp.json
    {
      "mcpServers": {
        "kini-docs": {
          "command": "npx",
          "args": [
            "mcp-remote",
            "https://docs.getkini.com/_mcp",
            "--timeout",
            "120000"
          ]
        }
      }
    }
    ```
  </Tab>

  <Tab title="Claude Code" icon="terminal">
    Add the MCP server using the Claude Code CLI:

    ```bash
    claude mcp add kini-docs --transport http --url https://docs.getkini.com/_mcp
    ```

    Or add it directly to `.mcp.json` in your project root:

    ```json .mcp.json
    {
      "mcpServers": {

    }
    ```
  </Tab>

  <Tab title="Claude Desktop" icon="bot">

    ```json claude_desktop_config.json
    {
    ```

  </Tab>

  <Tab title="Windsurf & Other Clients" icon="code">

## Step 2: Add Agent Instructions

Copy and paste the following prompt instructions into your project's agent rules file (`CLAUDE.md`, `.cursorrules`, `.windsurfrules`, `.copilot-instructions.md`, or your agent's system prompt).

```markdown
# Kini API Integration Context

## Overview
You are building an integration with the Kini API (https://api.getkini.com).
Kini connects recruitment platforms, job boards, and ATS (Applicant Tracking Systems) to sync jobs, candidates, applications, and webhooks.

## Core Reference
- Base URL: `https://api.getkini.com`
- Docs URL: `https://docs.getkini.com`
- Reader MCP endpoint: `https://docs.getkini.com/_mcp`

## Authentication & Headers
All requests must include:
- `Authorization: Bearer <API_KEY>` (generated in https://app.getkini.com/)
- `Company-Id: <COMPANY_ID>` (identifies the customer company; use the partner test company ID during testing)
- `Content-Type: application/json`

## Key Endpoints
- **Jobs API**:
  - `GET /jobs?pagination=true` — List jobs (pass `pagination=true` for paginated sets).
  - `POST /jobs` — Create a new job posting (not an upsert; query first to avoid duplicates).
  - `PUT /jobs/{id}` — Update an existing job.
  - `DELETE /jobs/{id}` — Archive a job.
- **Applications API**:
  - `POST /applications` — Submit candidate application to ATS.
  - `GET /applications?pagination=true` — List candidate applications (180-day retention window).
  - `GET /applications/{id}` — Retrieve candidate sync details.
- **Companies API**:
  - `GET /companies` — List accessible customer companies.
  - `GET /companies/{id}` — Get single company details and sync status.
- **Shop API**:
  - `POST /clickout/` — Generate clickout tracking link.
  - `POST /product_bookings/` — Book marketing/job channels.

## Webhooks
- `application_sync_status_update`: Sent when candidate is synced to ATS (`SUCCESS`, `FAILURE`, `EXPECTED_FAILURE`, `NOTSENT`).
- `job_update`: Sent when a job is created, updated, or archived in the ATS.
- `job_booking_status_update`: Sent when job booking status changes (`BOOKED`, `PUBLISHED`, `EXPIRED`, etc.).

## Best Practices
- Rate limits are 60 requests/minute per connected company.
- Attachments on `POST /applications` must stay within 20 MB raw files (27.5 MB base64 body limit).
- In case of `EXPECTED_FAILURE` on applications, inspect `failure_error` for details (e.g. `JobNotPublishedError` or duplicate detection).
```

## Step 3: Available Agent Tools

Once connected via MCP, your agent can call the `searchDocumentation` tool to look up live documentation, schemas, and implementation guides directly.

| Capability | What the agent can look up |
| --- | --- |
| **Endpoint schemas** | Request body formats, query parameters, path variables, and response schemas. |
| **Authentication rules** | Bearer token formats, header requirements, and company scoping rules. |
| **Webhook payloads** | Event names, payload structure, status enums, and failure error codes. |
| **Integration guides** | QuickApply flows (Indeed, Meta Lead Forms, Perspective), pagination, and error handling. |

## Environments & Testing

The Kini API operates on a single environment:

```text
https://api.getkini.com
```

When building and testing with your agent, use your assigned **test company ID** in the `Company-Id` header. Data created under your test company does not impact production customers. If you need your test company ID or API keys, check the [Kini Partner App](https://app.getkini.com/) or contact [tech@getkini.com](mailto:tech@getkini.com).
